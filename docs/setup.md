# Настройка

Пошаговый запуск трёх конвейеров: сбор `workflows/collect.json`, бот редактора `workflows/editor.json` и публикация по расписанию `workflows/publish.json`.

## Что нужно

- Docker с docker compose.
- Бот Телеграма и канал, где бот администратор с правом публикации.
- Ключ нейросети с совместимым с OpenAI интерфейсом: Groq, GigaChat через gpt2giga или любой другой.
- Публичный HTTPS-адрес для n8n: Телеграм присылает нажатия кнопок только на HTTPS. Подойдёт свой домен с обратным прокси или туннель.

## Бот и канал

1. В Телеграме написать [@BotFather](https://t.me/BotFather) команду `/newbot`, задать имя и адрес бота. В ответ придёт токен вида `123456:ABC...`: это `TELEGRAM_BOT_TOKEN`, его никому не показывать и не класть в репозиторий.
2. Создать канал (публичный или закрытый). В настройках канала: Администраторы, Добавить администратора, найти бота по адресу и оставить право «Публикация сообщений».
3. `TELEGRAM_CHANNEL_ID`: для публичного канала `@имя_канала`. Для закрытого нужен номер вида `-100...`: его можно увидеть в ответе `getUpdates` (ниже), если переслать боту любое сообщение из канала.
4. `EDITOR_CHAT_ID`: номер чата, откуда бот принимает нажатия. Написать боту любое сообщение и открыть в браузере `https://api.telegram.org/bot<токен>/getUpdates`: номер лежит в `message.chat.id`. Для личной переписки он совпадает с номером пользователя. Делать это до включения `editor.json`: пока у бота есть вебхук, `getUpdates` не работает ([Bot API, getUpdates](https://core.telegram.org/bots/api#getupdates)).

## Ключ нейросети

По умолчанию Groq. Ключ создаётся в [консоли Groq](https://console.groq.com/keys), это `LLM_API_KEY`. Адрес `LLM_BASE_URL=https://api.groq.com/openai/v1`, модель `LLM_MODEL` выбрать из [списка моделей Groq](https://console.groq.com/docs/models). Для другого поставщика поменять адрес, ключ и имя модели; для GigaChat поднять [gpt2giga](https://github.com/ai-forever/gpt2giga) и указать его адрес.

## Публичный адрес

Телеграм шлёт обновления бота только на HTTPS ([Bot API, setWebhook](https://core.telegram.org/bots/api#setwebhook)). Для постоянной работы нужен свой домен с обратным прокси (nginx, Caddy) на `127.0.0.1:5678`.

Для пробы хватит туннеля, например быстрого туннеля Cloudflare:

```
cloudflared tunnel --url http://localhost:5678
```

Он выдаст адрес вида `https://....trycloudflare.com`, его вписать в `WEBHOOK_URL`. У такого туннеля адрес меняется при каждом запуске: тогда обновить `WEBHOOK_URL`, перезапустить n8n (`docker compose up -d`) и выключить и снова включить `editor.json`, чтобы n8n заново зарегистрировал вебхук.

## Запуск n8n

```
cp .env.example .env
# заполнить N8N_ENCRYPTION_KEY (openssl rand -hex 32) и WEBHOOK_URL
docker compose up -d
```

n8n откроется на http://localhost:5678, при первом входе он попросит создать учётную запись владельца. Порт открыт только на этом компьютере; снаружи n8n доступен через прокси или туннель по адресу из WEBHOOK_URL.

Данные n8n и журнал `content-factory.sqlite` лежат в томе `n8n_data`. Резервная копия: `docker compose cp n8n:/home/node/.n8n ./backup`.

## Ключи и настройки

Доступ узлов к переменным окружения в n8n по умолчанию закрыт, и открывать его не нужно:

- `LLM_API_KEY` и `TELEGRAM_BOT_TOKEN` вводятся в учётные данные n8n (Credentials): ключ нейросети в учётные данные OpenAI с адресом из `LLM_BASE_URL`, токен в учётные данные Telegram. n8n хранит их зашифрованными ключом `N8N_ENCRYPTION_KEY`, в файлы конвейеров они не попадают.
- `LLM_MODEL`, `TELEGRAM_CHANNEL_ID`, `EDITOR_CHAT_ID` и `CF_DB_PATH` вписываются в узел «Настройки» в начале каждого конвейера.

## Конвейер сбора

1. В n8n: Workflows, Import from File, `workflows/collect.json`.
2. Учётные данные: в узле «Нейросеть» создать учётные данные OpenAI с ключом и Base URL (для Groq `https://api.groq.com/openai/v1`), в узле «Черновик редактору» учётные данные Telegram с токеном бота.
3. В узле «Настройки» вписать `LLM_MODEL`, `EDITOR_CHAT_ID` и тот же адрес в `LLM_BASE_URL`. Там же `MAX_ITEMS` (сколько новостей за запуск уходит в нейросеть), `MAX_LENGTH` (длина поста в промпте), `MIN_RELEVANCE` (порог оценки нейросети), `OVERLAP_WORDS` и `OVERLAP_MAX` (длина цепочки слов и доля дословных совпадений с описанием, выше которой редактор видит пометку).
4. Запустить вручную кнопкой Execute workflow, проверить, что черновики пришли в чат редактора, затем включить конвейер. По умолчанию он запускается раз в три часа.

Что делает конвейер: читает ленты из `src/sources.json`, отбирает новости по ключевым словам и журналу (повторы ссылок и похожие заголовки за 14 дней не проходят), отправляет каждую в нейросеть по одной раз в 3 секунды, разбирает ответ, собирает пост со ссылкой на источник и присылает черновик редактору с кнопками «Опубликовать», «Переписать», «Отклонить». Всё отклонённое лежит в журнале с причиной: стоп-слово, нет ключевых слов, похожий заголовок, ниже порога релевантности, ошибка запроса к нейросети.

## Бот редактора

1. Импортировать `workflows/editor.json`, в узлах «Телеграм», «Ответ на нажатие», «Правка черновика» и «Черновик редактору» выбрать те же учётные данные Telegram, в узле «Нейросеть» те же учётные данные OpenAI.
2. В узле «Настройки» те же `LLM_MODEL`, `EDITOR_CHAT_ID` и `LLM_BASE_URL`, что в конвейере сбора. Команды из других чатов не выполняются, на чужие нажатия бот отвечает «Нет доступа». Пустой `EDITOR_CHAT_ID` закрывает доступ всем.
3. Включить конвейер (Active). Телеграм шлёт обновления на адрес из `WEBHOOK_URL`, поэтому n8n должен быть доступен снаружи по HTTPS. У бота может быть только один такой адрес: второй конвейер с узлом Telegram Trigger на том же боте перехватит его.

Что умеет бот:

- «Опубликовать»: пост встаёт в очередь (статус `queued` в журнале), сообщение с черновиком получает строку «В очереди на публикацию», кнопки исчезают.
- «Отклонить»: запись отклоняется с причиной «отклонено редактором». Свою причину можно написать ответом (reply) на черновик: «Отклонить: реклама».
- «Переписать»: черновик уходит в нейросеть с пометкой (промпт `prompts/rewrite.md`), редактору приходит новый черновик с теми же кнопками. Пометку можно написать ответом на черновик любым текстом, например «короче, без цифр». Порог оценки здесь не применяется: редактор уже решил, что новость нужна. Если нейросеть не ответила или ответ не разобран, приходит прежний черновик с причиной.

Повторное нажатие на уже решённый черновик ничего не меняет в журнале, бот отвечает «Уже в очереди» или «Уже отклонено».

## Публикация по расписанию

1. Импортировать `workflows/publish.json`, в узле «Отправка в канал» выбрать те же учётные данные Telegram.
2. В узле «Настройки» вписать `TELEGRAM_CHANNEL_ID` (`@имя_канала` или номер вида `-100...`) и тот же `CF_DB_PATH`. Бот должен быть администратором канала с правом публикации.
3. Включить конвейер. Телеграм-триггера в нём нет, вебхук бота остаётся за `editor.json`.

Раз в 15 минут конвейер берёт из очереди пост, поставленный раньше других, и отправляет его в канал. Правила в `src/publish.config.json` (после правки `npm run build`):

- `minIntervalMinutes`: не чаще одного поста за столько минут (по умолчанию 60).
- `quietHours`: тихие часы по местному времени `timeZone`, по умолчанию с 23:00 до 08:00 по Москве. Посты ждут утра.
- `maxAttempts`: сколько раз пробовать отправить пост, который Телеграм не принимает (по умолчанию 3).

Принятый пост получает статус `published` и номер сообщения в канале. Ошибка Телеграма (бот не админ, неверный номер канала, сломанная разметка) пишется в поле `reason`, пост остаётся в очереди и уходит в следующий запуск. После `maxAttempts` неудач он остаётся в очереди с ошибкой, но больше не держит остальные. Повторов отправки внутри запуска нет: при обрыве связи после отправки повтор дал бы пост в канале дважды.

## ВКонтакте

Вместо канала Телеграма посты можно публиковать на стену сообщества ВКонтакте. Бот редактора при этом остаётся в Телеграме.

1. В узле «Настройки» конвейера `publish.json` вписать `PLATFORM=vk` и `VK_GROUP_ID`: номер сообщества цифрами. Если адрес сообщества вида `vk.com/club123456`, номер `123456`; при коротком адресе номер виден в разделе «Управление» сообщества. Запись уходит методом [wall.post](https://dev.vk.com/ru/method/wall.post) с `owner_id=-номер` и `from_group=1`, то есть от имени сообщества.
2. В узле «Отправка во ВКонтакте» создать учётные данные Query Auth: имя `access_token`, значение ключ доступа. В файл конвейера ключ не попадает.
3. Ключ доступа. По ответам разработчиков на форумах ключ сообщества для wall.post не подходит, нужен ключ пользователя, который администрирует сообщество, с правами `wall` и `offline` (без `offline` ключ быстро истекает). Как получить такой ключ и какие права нужны, сверить с документацией: [wall.post](https://dev.vk.com/ru/method/wall.post) и раздел о ключах доступа на dev.vk.com. Ключ даёт доступ к странице пользователя, хранить его только в учётных данных n8n.
4. Запустить конвейер вручную вне тихих часов: запись появилась на стене. Если нет, в выходе узла «Итог» будет код и текст ошибки ВКонтакте, они же в журнале с причиной «ошибка ВКонтакте: …».

Черновики в журнале собраны для Телеграма с разметкой HTML. Перед отправкой во ВКонтакте узел «Следующий пост» переводит их в простой текст: заголовок первой строкой, ссылка на источник последней. Число попыток, интервал и тихие часы те же, что для Телеграма.

## MAX

Посты можно публиковать в канал MAX. Бот редактора при этом остаётся в Телеграме. Живой отправки в MAX не было: узел собран по документации, при первом запуске проверить по пункту 5 ниже.

1. Создать бота MAX: через платформу для партнёров business.max.ru или через @MasterBot в самом MAX. Ключ бота выдаётся при создании.
2. Добавить бота в канал администратором с правом писать сообщения.
3. Узнать номер канала (chat_id): у каналов он обычно отрицательный. Его отдают методы API бота (например, список чатов бота `GET /chats`), сверить с [документацией](https://dev.max.ru/docs-api).
4. В узле «Настройки» конвейера `publish.json` вписать `PLATFORM=max` и `MAX_CHAT_ID`: номер канала цифрами, с минусом, если он есть. В узле «Отправка в MAX» создать учётные данные Header Auth: имя `Authorization`, значение ключ бота. Ключ в адресе запроса MAX больше не принимает, в файл конвейера он не попадает.
5. Запустить конвейер вручную вне тихих часов: сообщение появилось в канале. Если нет, в выходе узла «Итог» будет код и текст ошибки, они же в журнале с причиной «ошибка MAX: …».

Сообщение уходит методом [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages) с разметкой HTML (`format: html`), текст до 4000 знаков. Чтобы посты собирались сразу под MAX, в «Настройках» конвейера сбора тоже указать `PLATFORM=max`. Число попыток, интервал и тихие часы те же, что для Телеграма.

## Версия n8n и Node

Образ закреплён на `n8nio/n8n:2.41.5`. По Dockerfile этой версии в репозитории n8n (`docker/images/n8n/Dockerfile`, проверено 02.10.2026) образ собран на Node 26.7.0, поэтому журнал работает на встроенном `node:sqlite` без сторонних пакетов. Узлам Code модуль разрешён переменной `NODE_FUNCTION_ALLOW_BUILTIN=node:sqlite`, остальные встроенные модули закрыты.

При обновлении образа сверить версию Node: нужна 22.5 или новее.

## Как код из `src/` попадает в n8n

Решение: код вклеивается в узлы Code файлов `workflows/*.json` скриптом сборки, тест проверяет, что вклеенное совпадает с `src/`.

Почему не подключение папки `src/` в контейнер: в n8n 2.x узлы Code выполняются в отдельном процессе (task runner), и `require` там пропускает только модули из списков `NODE_FUNCTION_ALLOW_BUILTIN` и `NODE_FUNCTION_ALLOW_EXTERNAL`, сравнивая строку запроса целиком. Пришлось бы вписывать в список абсолютные пути к файлам и держать одинаковые пути в compose и в конвейерах. Вклеенный код работает в любой установке n8n, в том числе облачной, а импорт остаётся одним файлом.

Код каждого узла Code лежит в `src/nodes/`, узел связан с файлом заметкой «Код: src/nodes/...». Строка `// @include src/filter.js as filterLib` при сборке заменяется содержимым файла. Править код только в `src/` и `prompts/`, затем `npm run build`. Ручная правка кода внутри JSON не пройдёт тест.

## Проверка по шагам

1. `docker compose ps`: контейнер `n8n` в состоянии running, http://localhost:5678 открывается.
2. Публичный адрес из `WEBHOOK_URL` открывает ту же страницу входа n8n.
3. Конвейер сбора, запуск вручную: в истории запуска узел «Чтение RSS» вернул новости, «Отбор» пропустил хотя бы часть, в чат редактора пришли черновики с кнопками. Если черновиков нет, смотреть выход узлов «Отбор» и «Разбор и пост»: новости не прошли по ключевым словам, оказались ниже порога или нейросеть вернула ошибку.
4. Бот редактора включён: на одном черновике «Отклонить» дописывает строку «Отклонено (...)», на другом «Переписать» присылает новый черновик, на третьем «Опубликовать» дописывает «В очереди на публикацию».
5. Публикация, запуск вручную вне тихих часов: пост из очереди появился в канале. Если нет, в выходе узла «Итог» будет текст ошибки Телеграма (чаще всего бот не администратор или неверный `TELEGRAM_CHANNEL_ID`).
6. Включить конвейеры сбора и публикации (Active), бот редактора уже включён.
